### 1.3 Start-up sequence (StartAll, +W.s:9224-9458)
Inputs: a0 = interpreter config block (`PI_ParaTrap`, +Interpreter_Config.s:27-34), a1 = mouse bank, a2 = default palette, a3 = font name, d0 = AMOSHere, d1 = Amiga-A key.
- Mouse.abk must start "AmSp", >=4 images; colours 16-31 of the default palette are copied from the palette stored after the mouse sprite images (+W.s:9276-9295).
- System font opened: topaz (or name in a3) size 8, flags $41 (+W.s:9298-9325) -> `T_DefaultFont` (used as RastPort font for graphic `Text`).
- `T_DefWX=129`, `T_DefWX2=129-16`, `T_DefWY=config+10 (=50)`, `T_DefWY2=DefWY-8` (+W.s:9389-9393).
- Init order: HsInit(sprite lines=config+16 = 128) -> BbInit(nb bobs=config+8 = 68) -> RbInit -> CpInit(copper list length=config+12 = 12K) -> EcInit -> SyInit -> VBLInit -> WiInit (+W.s:9395-9409), then `Wi_MakeFonte` (+W.s:9436) builds the text font.
- EcInit (+W.s:2440-2471): `T_EcYMax = 311+EcYBase` PAL, `261+EcYBase` NTSC (ExecBase VBlankFrequency at 530).

### 1.4 How the interpreter drives the library each frame
- VBL interrupt (`VblIn`, +W.s:10346-10458) runs at 50 Hz: interlace field pointer swaps, pending screen-swap pointer pokes, hardware-sprite copper update (`HsPCop`), increments `T_VBLCount/T_VBLTimer`, decrements `T_EveCpt`, **sets `BitVBL` (bit 15) in `T_Actualise`**, calls extension VBL routines, `MousInt`, colour `Shifter`, `FlInt` (flash), `FadeI` (fade), and if `T_SyncOff==0` the AMAL `Animeur`.
- The interpreter calls `Test_Normal` between instructions (+ILib.s:904-909): if `T_Actualise` bit 15 set -> `Test_Force` (+ILib.s:915-1032) which, masked by `ActuMask` and throttled by `VBLDelai`, performs in this order:
  1. `BitBobs`(13): `SyCall EffBob; ActBob; AffBob; EcCall SwapScS` (bob erase/move/draw + swap all double-buffered screens)
  2. `BitSprites`(14): `SyCall ActHs; AffHs`
  3. extension tests
  4. `BitEcrans`(12): `EcCall CopMake` (rebuild copper list = recompose screens)
  5. Every handling; clears BitVBL.
- Bit numbers: +Equ.s:827-834 (BitControl 8, BitMenu 9, BitJump 10, BitEvery 11, BitEcrans 12, BitBobs 13, BitSprites 14, BitVBL 15). `Bob Update Off/On`, `Sprite Update Off/On`, `Update Off/On` toggle bits 13/14 of ActuMask (+Lib.s:11423-11477, byte-level bset #5/#6 on the high byte). `Autoview Off` clears BitEcrans in ActuMask; `View` forces CopMake (+Lib.s:9065-9082).
- Screen functions that change geometry only set `BitEcrans` in `T_Actualise` (and bump `T_EcYAct` when vertical layout/priority changes): e.g. `EcTout`/`EcOtoV` (+W.s:3116-3122). So **Screen Display/Offset/To Front etc. take effect at the next VBL-driven update, not immediately.**

### 2.2 Screen Open (+Lib.s:8920-8969 -> EcCree +W.s:2882-3122)
- Mode word from BASIC: `Hires=$8000`, `Laced=$4`, `Lowres=0`; masked `and #$8004` (+Lib.s:8924).
- colours -> planes: 2->1, 4->2, 8->3, 16->4, 32->5, 64->6 (EHB: 6 planes without HAM => hardware Extra-Half-Brite, colours 32-63 = colour(n-32) at half intensity, i.e. each component >>1). `4096` colours => HAM: lowres only, 6 planes, mode |= $0800, NbCol=64 (+Lib.s:8926-8934). Hires limited to 4 planes (+Lib.s:8950-8953). Illegal count => error 5.
- EcCree validation: Tx rounded down to multiple of 16, 0<Tx<1024, 0<Ty<1024, 1<=planes<=6 (+W.s:2886-2897); re-opening an existing number closes it first.
- Palette: copies 32 words from DefPal (+W.s:2918-2922). DefPal default = `$000,$A40,$FFF,$000,$F00,$0F0,$00F,$666,$555,$333,$733,$373,$773,$337,$737,$377` + colours 16-31 from mouse bank (+Interpreter_Config.s:94-97, +W.s:9291-9295).
- New screen becomes current and goes to the FRONT (`EcFirst`, +W.s:3025).
- Default display (+W.s:3030-3052): WX=DefWX(129), WY=DefWY(50); WTx = Tx (Tx/2 if hires), WTy = Ty; if WTx >= 336 then WX=DefWX2 (113); if Ty>=256 (>=512 for lace) WY = DefWY2 (42).
- Opens a full-screen text window 0 (Tx/16*2 columns = Tx/8, Ty/8 lines) (+W.s:3056-3069), sets graphics defaults: InkA=window pen, InkB=paper, mode JAM2 (1), line $FFFF, clip = whole screen, default font (+W.s:3073-3108).
- BASIC then makes **colour 3 flash** with string message 46: `(000,2)(440,2)(880,2)(bb0,2)(dd0,2)(ee0,2)(ff2,2)(ff8,2)(ffc,2)(fff,2)(aaf,2)(88c,2)(66a,2)(226,2)(004,2)(001,2)` (+Lib.s:8960-8967, +Interpreter_Config.s:158) unless only 1 plane.
- Default screen (screen 0 at start): 320x256, 4 planes, 16 colours, lowres (+Interpreter_Config.s:89-93).

### 2.3 Display / Offset semantics
- `Screen Display n,x,y,w,h` -> `EcView` (+W.s:3252-3276): stores into EcAWX/EcAWY/EcAWTx/EcAWTy with flag bits; omitted params (`EntNul`) are untouched. Applied in `EcCopper` (+W.s:5713-5772):
  - `EcWY = y + EcYBase`, negative -> 0 (+W.s:5718-5722).
  - `EcWX = x & $FFF0` (16-pixel granularity!) (+W.s:5727-5729).
  - `EcWTy = min(h, Ty)`; ignored if 0; **halved for interlaced screens** (+W.s:5736-5744).
  - `EcWTx = min(w & $FFF0, Tx)` where Tx is halved for hires, i.e. **width is in lowres pixels** (+W.s:5749-5759).
- `Screen Offset n,dx,dy` -> EcAVX/EcAVY applied to EcVX/EcVY (+W.s:3522-3533, 5762-5770).
- Hardware coordinates: X = lowres colour clock position; standard left edge is 128 (`DefWX=129` & $FFF0). Screen pixel column c (lowres) appears at hardware X = WX + c  (hires: WX + c/2). Y = PAL raster line (standard top 50 in AMOS default; frame lines 0..311 PAL / 0..261 NTSC).
- Copper DIWSTRT horizontal = WX+1 (=$81 for 128), DIWSTOP horizontal = WX+1+WTx, vertical always $01..$137 (vertical windowing done with DMA on/off) (+W.s:6367-6374).
- Right clamp: if WX+1+WTx >= 481 (lowres) / 465 (hires) the width is shortened; if WX+1+WTx <= 176 the start is moved (+W.s:6345-6365).

### 2.4 Priority & composition (`EcCopper`, +W.s:5700-6050)
- `T_EcPri` = list of screen pointers, front first, terminated by -1, (0 entries skipped). `EcFirst` inserts at the head (+W.s:3279-3296); `EcLast` moves to the tail (+W.s:3299-3314). Hidden screens (EcFlags bit7) are ignored.
- Slicing (+W.s:5786-5868) builds `T_EcBuf` triples (y, yend, priority-index | $8000 for "end" events). For each screen the occupied range is **[WY-1, WY+WTy)** in hardware lines (+$1000). Top clipped at line EcYStrt-1 = 25 (a marker is inserted, +W.s:5826-5832); starts at >= EcYMax-2 dropped, ends clipped at EcYMax-1.
- Visibility (+W.s:5872-5964): at each start event, the screen is emitted only if no screen with a *lower priority index* (more to the front) covers that line; at an end event, the frontmost still-covering screen is re-emitted. The resulting `T_EcCop` list is: `+line, screenptr` (start) / `-line` (end) / 0.
- **Equivalent per-scanline rule for a shader**: for hardware line L, the owning screen S is the frontmost non-hidden screen with `WY-1 <= L < WY+WTy`. Copper emission per owned slice starting at line L0:
  - Line L0 (`EcCopHo`, +W.s:6272-6490): WAIT L0; **bitplane DMA off**; COLOR00-15 := S.pal[0..15]; bitplane pointers; DIW/DDF/modulos/BPLCON0-2. So line L0 is drawn entirely in S.colour0 (no bitmap).
  - Line L0+1: DMA on; COLOR16-31 := S.pal[16..31] (+W.s:6449-6469).
  - Bitmap row shown on hardware line L (L>L0) = `(L - WY) + VY` (lace: `2*(L-WY) + VY*?` — pointer offset `d1 = (L0-WY+1)*2` rows then modulo skips one row; in the odd field the VBL adds one row, +W.s:10349-10381 => line shows row `2*(L-WY)+field`, plus VY).
  - Horizontal: bitmap column = `VX + (X - WX)` for lowres, fine scroll via BPLCON1 when VX&15 != 0 (+W.s:6387-6423); outside [WX+1, WX+1+WTx) the line shows COLOR00 = S.pal[0] (border colour is per-line, i.e. the owning screen's colour 0 extends across the whole scanline).
  - When the slice ends at line E (`EcCopBa`, +W.s:6717-6724): DMA off, COLOR00 := `T_EcFond` (Colour Back, default 0). Lines with no screen therefore show Colour Back.
  - If a screen behind becomes visible at line E it gets its own setup line E (colour 0 only) and bitmap from E+1.
- Copper list end `$FFFFFFFE`; lines >=256 need the `$FFDF FFFE` wrap wait (WaitD2, +W.s:6727-6738). Copper list starts with a `$1003FFFE` wait and 16 sprite pointer moves ($120-$13E) (CpInit, +W.s:6743-6769). Lists are double-buffered (CopLogic/CopPhysic swapped, +W.s:6038-6046).
- `T_CopMark` (+WEqu.s:160-163): per screen 128 bytes = 16 longs of copper addresses where colours 0-15 are loaded + 16 longs for colours 16-31; used to poke palette changes (Colour, Palette, Flash, Shift, Fade) directly into every copper slice **without** rebuilding. After that, `CopL1*EcMax` area holds per-screen (64 bytes) list of (copper address, offset) pairs for bitplane pointers, used by Screen Swap.
- Colour registers: only 32 hardware colours per screen; `Colour n,$RGB` masks n&31, value&$FFF (+W.s:3817-3837). `Palette` skips negative entries (+W.s:3848-3880).

### 2.5 Dual playfield (`Duale` +W.s:2790-2843, copper `CreeDual` +W.s:6494-6713)
- `Dual Playfield s1,s2`: both screens must have identical EcCon0 resolution bits, <=3 planes each (<=2 if hires), planes equal or s2 = s1+1... (code: allowed if n1==n2 or n2+1==n1 where a0=s1, a1=s2). s1 gets BPU = n1+n2 and DPF bit 10; PF2 sprite priority copied from PF1 bits (+W.s:2834-2838); s2 is hidden and its EcDual = -(s2+1); s1 EcDual = s2+1.
- Copper: s1's planes go to BPL1,3,5 (odd hardware planes = playfield 1) and s2's planes to BPL2,4,6 (playfield 2), each with own VX/VY, modulo and BPLCON1 scroll nibble (PF1 low nibble, PF2 high nibble). DIW/size taken from s1. Palette = s1's palette only: PF1 uses colours 0-7, PF2 uses colours 8-15 (hardware rule, 0 / 8 transparent).
- `Dual Priority` toggles BPLCON2 bit 6 (PF2PRI) (+W.s:2846-2871).
- If s2 is closed the master reverts to single playfield (+W.s:6500-6510).

### 2.6 HAM / EHB
No special code in +W.s: HAM = BPLCON0 bit 11 with 6 planes lowres; EHB = 6 planes lowres without HAM (hardware behaviour). A renderer must implement: HAM6 (planes 5-6 control: 00 = palette[low4], 01 = modify blue, 10 = modify red, 11 = modify green, previous pixel colour carried left-to-right from the DIW start, starting with COLOR00); EHB (index>=32 => palette[index-32] with each 4-bit component >>1).

### 2.7 Double buffering / Screen Swap / Autoback
- `Double Buffer` (+W.s:2744-2784) allocates second plane set (Logic != Physic), copies content, sets BitDble and EcAuto=2.
- `Screen Swap` (+W.s:2598-2648, all screens +W.s:2651-2703): swaps EcLogic<->EcPhysic, updates EcCurrent and BitMap planes, and queues new pointers in `T_SwapList` that the VBL pokes into the copper bitplane pointer moves (+W.s:10385-10411) => swap is effective at next VBL (not for interlaced screens or when copper is off).
- Autoback (`Autoback n`, n=0..2 stored in EcAuto, +Lib.s:9510-9518) wraps every graphics call (GfxF0 +Lib.s:11257-11284, and Cls +W.s:3666-3677):
  - 0: draw only to the logic screen.
  - 1 (double buffered): draw in logic, then redraw the same thing in physic (TAbk2 mode1 switches EcCurrent to physic, TAbk3 restores) (+W.s:3564-3606).
  - 2 (double buffered): WVbl + BobEff (erase bobs), draw in logic, BobAct/BobAff/ScSwapS/WVbl/BobEff, draw again, BobAct/BobAff/ScSwapS/WVbl (+W.s:3553-3616). Single-buffered: BobEff before, BobAct+BobAff after (TAbk4 +W.s:3618-3627).
  - Rust simplification: render the primitive into both buffers.
- `Screen Clone` (+W.s:2706-2741): copies the structure (no zones/windows/pattern/font), sets BitClone; shares bitmap; goes to front; drawing on a clone is refused (`EcMarch` +W.s:3776-3787 error 4).

### 2.8 Rainbows (+W.s:3889-4161 commands; copper merge +W.s:6052-6267)
- 4 rainbows (`NbRain=4`), struct +WEqu.s:142-154: RnDY (first hw line+$1000), RnFY (end), RnTY (height), RnBase, RnColor, RnLong (buffer bytes), RnBuf (table of $RGB words, one per line), RnAct (pending flags), RnX (base), RnY, RnI (height).
- `Set Rainbow n,colour,length,r$,g$,b$` (`TRSet` +W.s:3964-4090): colour must be 0..15 (PalMax) else syntax error; allocates `length` words. Each component string is a list of `(speed,step,count)` triples (`RainTok` +W.s:4093-4134; speed>0, count>=0). Generation per line (Trs1 loop +W.s:4040-4075): for each of R,G,B independently: `cpt--`; when it reaches 0: `cpt=speed; value=(value+step)&15; nb--`; when nb hits 0 load next triple (wrapping to the first): `cpt=speed, step, nb=count`. Initial value = nibble of the start colour d7 (R=bits 8-11, G=4-7, B=0-3). Initial cpt=1, nb=1 so the first triple loads on line 0 (and value is incremented by 0 on that line).
- `Rainbow n,base,y,h` (`TRDo` +W.s:3916-3938): sets RnX(base offset into the table), RnY (hardware line, min 28; stored +EcYBase), RnI (height); applied at next CopMake (+W.s:6053-6100).
- Composition: for hardware lines in [RnDY, RnDY+RnTY), colour register RnColor is overridden by `RnBuf[(L - RnDY + RnBase) mod (RnLong/2)]` regardless of which screen owns the line (copper MOVE each line; also patches the palette load in screen setup lines). Outside, the owning screen's colour returns (+W.s:6108-6170). `Rainbow Del` (+W.s:4137-4161), `Rain(n,i)=` var access (`TRVar` +W.s:3941-3954). `Rainbow Hide/Show` toggles `T_RainBow` (+W.s:3890-3896).

### 2.9 Colour effects run by VBL
- **Flash** (`FlStart` +W.s:5281-5361, interrupt `FlInt` +W.s:5654-5695): up to 16 flashing colours (FlMax) across screens; string `(RGB,delay)(RGB,delay)...` up to 16 entries, RGB 3 hex digits, delay in VBLs (>0). Cycles forever. `Flash Off` stops current screen's flashes. `Flash n,""` stops colour n.
- **Shift** (`ShStart` +W.s:5391-5413, `Shifter` +W.s:5440-5494): one shift at a time: every `speed` VBL rotates palette entries c1..c2 (c1<c2) of the current screen; direction flag 0 = "up" (colour[i] <- colour[i-1]), else down; rotate flag 1 = wrap the end colour around, 0 = shift (end colour duplicated).
- **Fade** (`FadeTOn` +W.s:5515-5564, `FadeI` +W.s:5569-5648): one fade at a time on the current screen; every `speed` VBLs each R,G,B nibble of each colour moves 1 step towards the target; target entries <0 are left alone; stops when all reached.
- Order inside VBL: Mouse, Shifter, Flash, Fade, AMAL (+W.s:10436-10452).

### 2.10 Copper Off mode (user copper lists) (+W.s:6790-6907)
`Copper Off` stops automatic list building; `Cop Reset`, `Cop Wait x,y[,maskx,masky]` (x,y <313; word1=(y<<8)|((x>>1)&$FE)|1; auto-inserts the $FFE1 wrap for y>=256), `Cop Move addr,val` (addr<512, even), `Cop Movel`, `Cop Swap`, `=Cop Logic`. Error 1 "copper not disabled", 2 "list too long", 3 "param out of range".

### 2.11 Misc
- `Cls col,x1,y1 to x2,y2` (+W.s:3636-3738) blitter fill, coordinates clamped to screen, x2/y2 exclusive; per-plane bit of colour.
- `Set Clip` (+W.s:4187-4239): x2<=Tx, y2<=Ty, x1<x2, y1<y2; stored exclusive; installed as a layers.library clip region (+W.s:4244-4298).
- Fonts for graphic `Text`: Amiga diskfont/graphics.library (`Get Fonts` AvailFonts, 10-byte TextAttr entries; `Set Font n` opens RAM/ROM font else disk font, +W.s:4816-4982). Default graphic font = topaz 8 (`T_DefaultFont`).
- `=Ntsc` and max raw line (`TMaxRaw` returns 311 or 261) (+W.s:2583-2595).
